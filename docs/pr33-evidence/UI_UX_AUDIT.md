### Manual Slot 1 persistence — verified in a persistent profile

A controlled test used Chromium `launchPersistentContext` with a dedicated disposable profile and the same origin `http://127.0.0.1:8060/` throughout. The browser was not launched with certificate bypass flags. The game created a QA-only company, saved it through the normal Save Game UI to Manual Slot 1, then the page was reloaded and the entire Chromium context/browser process was closed. A fresh Chromium process reopened the exact same user-data directory and origin.

After the full close/reopen, the Load Saves UI showed both records in the same IndexedDB `/userfs` database (version 21): autosave at Day 2 (after advancing one day) and Manual Slot 1 at Day 1. Loading Manual Slot 1 restored Day 1 and MYR 5,000; autosave remained a separate Day 2 snapshot at MYR 4,994. No JavaScript errors were recorded. Screenshots document save, reopen, the divergent records, and the loaded manual snapshot.

**Conclusion:** Manual Slot 1 persistence is **PASS for this controlled same-origin, same-persistent-profile cycle**. The prior conflicting blank-slot report was not reproduced. The independent automation path used inconsistent navigation coordinates/profile setup; a later replay identified coordinates that landed on the wrong main-menu action. Browser profiles also have separate IndexedDB storage, so a different profile cannot be used as evidence for the first profile's records. This is an automation/test-environment discrepancy, not a confirmed game persistence defect. No save schema or game data was changed. This verifies one complete close/reopen cycle; repeated cycles and other browsers remain untested.

The prior layout placed the dialog header within the scrollable tool body, so scrolling long controls hid Close and Lock. `main.gd` now uses a viewport-filling panel with `DeveloperConsoleHeader` outside `DeveloperConsoleScroll`; the tools remain in the existing vertical scroll. `developer_console_ui_test` asserts this hierarchy, the visible bounds of Close/Lock, and last-option reachability for all nine approved viewport sizes.
