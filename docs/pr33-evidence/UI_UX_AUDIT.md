### Manual Slot 1 and autosave persistence — conditional pass; rapid-close defect confirmed

A controlled test used Chromium `launchPersistentContext` with a dedicated disposable profile and the same origin `http://127.0.0.1:8060/` throughout. The browser was not launched with certificate bypass flags. The game created a QA-only company, saved it through the normal Save Game UI to Manual Slot 1, then the page was reloaded and the entire Chromium context/browser process was closed. A fresh Chromium process reopened the exact same user-data directory and origin.

After a full close/reopen with a deliberate post-save wait, the Load Saves UI showed both records in the same IndexedDB `/userfs` database (version 21): autosave at Day 2 (after advancing one day) and Manual Slot 1 at Day 1. Loading Manual Slot 1 restored Day 1 and MYR 5,000; autosave remained a separate Day 2 snapshot at MYR 4,994. A second controlled cycle performed an actual one-unit purchase, confirmed the autosave after same-tab reload and full Chromium process close/reopen, saved that state to Manual Slot 1, closed/reopened the same profile, loaded Slot 1, and confirmed PO-0001 remained In Transit. However, a separate same-profile run saved Slot 2, saw the occupied-slot confirmation in the UI, closed Chromium about 0.4 seconds after save, and then found Slot 2 empty after reopening; a previously persisted Slot 1 remained. This falsifies an unconditional persistence PASS.

**Conclusion:** A delayed manual save and autosave can persist, but **rapidly closing after the UI reports a manual save can lose it**. The root cause is consistent with Godot's Web IDBFS queue: `queuePersist` schedules an asynchronous IndexedDB transaction, while the game's save success UI is updated before durable sync finishes. The earlier conflicting results partly came from automation profile/navigation mistakes, but the same-profile rapid-close reproduction establishes a genuine durability defect. Manual Slot 1 is therefore **FAIL for immediate close/reopen acceptance**. No schema or existing player data was changed. The durability race is unresolved and blocks save acceptance; other browsers and physical Safari remain untested.
